# Rapport d'audit SEO / GEO / AEO : Vigi-FR, novembre 2026

Date de l'audit : 7 novembre 2026. Site : https://vigi-fr.vercel.app. Premier rapport : aucune comparaison mensuelle possible (voir E).

**Convention de lecture.** *Observé* = constaté par moi sur le code, le site en ligne ou un test local reproductible. *Estimé* = raisonnement, non mesuré. *Non mesuré* = nécessite une connexion que je n'ai pas (Search Console, Bing Webmaster Tools, analytics). Aucun score de position, aucun trafic ni aucune indexation n'est affirmé dans ce rapport.

### GEO : règles d'exploration, vérifiées

Aucun blocage. `User-agent: *` autorise tout ; j'ai nommé explicitement `OAI-SearchBot`, `ChatGPT-User`, `GPTBot`, `PerplexityBot`, `Perplexity-User`, `Claude-SearchBot`, `Claude-User`, `ClaudeBot`, `Google-Extended`, `Applebot-Extended` pour documenter la politique. À savoir :

- **Autoriser l'exploration n'implique ni indexation ni citation** dans les réponses des assistants : rien ne permet de le garantir.
- `GPTBot`, `ClaudeBot`, `Google-Extended`, `Applebot-Extended` concernent surtout l'entraînement ou l'usage dans des modèles ; `OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot` concernent la recherche. **Décision éditoriale pour vous** : j'ai tout autorisé (site d'intérêt public, données CC BY). Si vous préférez refuser l'entraînement, passez ces robots-là en `Disallow: /` sans toucher aux robots de recherche.
- `llms.txt` n'est pas un facteur de classement ; son adoption par les moteurs de réponse n'est pas confirmée.
- FAQPage : Google ne montre plus ces résultats enrichis que pour certains sites institutionnels ou de santé. Le balisage est ici correct et fidèle au texte visible, mais **n'apportera probablement pas d'affichage enrichi sur Google** (estimé).

### Contrôle qualité effectué (observé)

- `npm run check` : syntaxe de tous les scripts OK. Génération **déterministe** (deux générations successives identiques : pas de commits parasites en CI).
- `node tools/verify-site.mjs` : 0 erreur, 0 avertissement. Contrôle : 117 titres, 117 descriptions et 117 h1 uniques ; canonical ; JSON-LD valide (graphe, `@id`, fil d'Ariane, FAQ vs texte visible, Dataset) ; liens internes et ancres ; aucune page orpheline ; sitemap ↔ pages ; clé IndexNow ; aucune hiérarchie de titres sautée sur 118 pages.
- Navigateur (Chromium) : 13 pages, console propre ; JS désactivé : contenu complet lisible ; jauge unique sans doublon ; bascule carte/liste, filtre, onglets, palette de recherche fonctionnels ; masquage correct si les données en ligne sont plus récentes que le HTML ; aucun débordement de 360 à 1600 px ; axe-core : 0 violation.
- Génération avec données absentes ou corrompues : pas de plantage, pas de chiffre inventé.
- Jeu de données **de test** (schéma 3 synthétique, jamais commité) utilisé pour exercer les chemins J0 et météo. `data/fwi.json` livré est le fichier réel d'origine.

## D. Opportunités (classées par potentiel)

1. **Lancer le workflow à la main une fois après déploiement** (Actions → « Run workflow »). Les données passent au schéma 3 (échéance du jour, météo) et toutes les pages se régénèrent. Vérifier ensuite que le commit contient aussi les pages.
2. **Brancher Search Console et Bing Webmaster Tools** : propriété Google déjà revendiquée par le fichier `google330aec82e0a58baf.html` (à confirmer dans la console) ; soumettre `sitemap.xml` ; dans Bing, importer la propriété depuis Google ou ajouter la balise `msvalidate.01` (je ne peux pas la générer). Suivre « Pages » (indexation) et « Core Web Vitals » dès qu'il y a du trafic.
3. **Vraie différenciation départementale** : c'est le levier de fond. Deux jeux de données publics à intégrer **après vérification des licences et des chiffres** (je n'ai rien inséré de mémoire) : la base BDIFF (historique des incendies de forêt) et l'Inventaire forestier de l'IGN (taux de boisement). Une page « 30 derniers jours » par département est aussi réalisable en archivant chaque jour le fichier de données.
4. **Mentions légales et identité de l'éditeur** : la page « À propos » ne nomme pas d'éditeur. Pour la confiance (E-E-A-T) et la conformité LCEN, ajouter l'identité ou la structure responsable et un moyen de contact. Je ne peux pas l'inventer.
5. **Nom de domaine propre** : un sous-domaine `vercel.app` limite la construction d'autorité de marque. Si vous en prenez un, prévoir des redirections 301 permanentes depuis l'ancienne adresse et mettre à jour `SITE_URL`.
6. **Publier le jeu de données sur data.gouv.fr** (démarche légitime de visibilité ; aucun lien artificiel) et le référencer depuis `/donnees/`.
7. **Hygiène** : le workflow signe les commits avec une adresse e-mail personnelle, publique dans le dépôt ; envisager l'adresse « noreply » de GitHub. Revoir aussi la méthode d'amorçage (30 jours) : le code de sécheresse DC réagit en plusieurs semaines, donc une série plus longue pourrait mieux le représenter (point méthodologique à valider avant tout changement, il modifie les niveaux publiés).
